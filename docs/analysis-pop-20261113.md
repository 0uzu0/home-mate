## 1. 读了三套实现

- **B**（线上）：`home-mate-device-gateway-b/crates/gateway/src/firmware/{bringup.rs,mod.rs,alsa.rs,loudness.rs}`

- **E**（RUI 的基线）：EchoMuse `50bbbc33` 的 `pcm_speaker.go`——启动时一次开功放，之后连续写零，段间不停流，

## 2. 逐机制对照（Codex 原表，行号已复核）

| 瞬态机制 | B | A | E |
|---|---|---|---|
| 功放使能/关闭 | 启动一次（`bringup.rs:103`） | **每播开关**（`pcm.c:303,345`） | 服务级（E:332,828） |
| DAPM 上下电 | 路由固定；XRUN/flush 可重启声路（`alsa.rs:299,315`） | 逐次 PCM 生命周期有风险（`pcm.c:276,347`） | 路由先设、PCM 常驻（E:309,329） |
| open/close/drain | 自然结束不 drain（`mod.rs:938`）；flush 仍 DROP→START（`alsa.rs:314`） | **DRAIN 早于静音关功放**（`pcm.c:175,345`） | Close 才拆（E:795,826） |
| 首末样本/DC 台阶 | 有淡变，但 EOS 晚到会漏尾（`mod.rs:870`） | 本助手无归零保证（`pcm.c:320`） | 本文件无首末归零保证（E:560） |

## 3. 本会话复核后确认的 B 侧三个真缺陷

这三条都只在**流式播放**（云 TTS 逐句下发）上出现，整段 WAV（本地"在呢"、诊断素材）不会触发：

1. **不足一个 period 时不写也不补零**（`mod.rs:817-819, 855-859`）：
   写入分支要求 `pending.len() >= 2048` 或 `eos && 非空`；静音分支要求两个通道**都空**。
   若某通道有 1…2047 帧在等下一块数据，**两条分支都不走** → 该轮迭代不写 DAC → 缓冲区耗尽 → XRUN。
   流式 TTS 的句间空档正好落在这个窗口里，听感就是句首/句末的"断电"声。
2. **短写被当成整周期**（`alsa.rs:293-296`）：`writei` 成功时返回 `x.frames`，但调用方
   （`mod.rs:869`）只用 `if let Err`，把返回值丢掉；同时没有检查 `x.result`
   （ALSA 旧 ioctl 的错误在 `result` 里，可能为负而 `ioctl` 返回 0）。短写/失败会被静默忽略。
3. **EOS 晚到就没有尾淡变**（`mod.rs:869-871`）：`a_last = voice.eos && pending.is_empty()`，
   而流式播放的 `PlayEnd` 常常在最后一块数据之后才到 → 最后那个 period 没有淡出 → 末样本台阶 → 哒声。

第 4 条（`loudness` 在暂时断粮时清延迟线、`mod.rs:975`）当前不生效——线上是 `--loudness off`；
但将来开回响度时必须一起修：只在真正结束（收到 EOS/停止）时排空尾部。

## 4. 两入口判别实验（下一步，不需要我在场也能做一半）

同一段"在呢"，固定位置外接麦克风连录，同步读 ch8 环回（DAC 侧数字轨）与功放开关读回：

| 观察 | 结论 |
|---|---|
| 本地整段 + 云 TTS **都爆** | 共同原因在输出启停/时钟（功放边沿、DAPM、DAC 静音边沿），与素材和通路无关 |
| 只有**云 TTS** 爆 | 上面 §3 的三条（断供/EOS/短写）——修完应消失 |
| 只有**本地整段**爆 | 素材首末样本、整段路径的淡变/填充或入口生命周期 |
| 全零 WAV 也爆 | 排除素材/DC/淡变作为唯一原因（A 已用这条反证过自己的启动脉冲） |

`--loudness off` 复播仍爆即排除限幅器；ch8 在爆音处连续准确则削弱"数字断供"解释
（但 ch8 是数字环回，不能证明 I2S 电气时钟正常）。

## 5. 最小改动清单（B，按上面的顺序）

1. 不足一个 period 时**继续送零并保留已有数据**（把静音分支的条件从"两通道都空"改为
   "任一通道无整周期可写"），这样 DAC 永不断流。
2. `writei` 按 `x.frames` 续写、检查 `x.result`，短写不再当成功。
3. 尾淡变不依赖 EOS 到达时机：最后一块数据已知剩余帧数时提前应用淡出（或在 EOS 到达后
   再补一个已淡出的尾 period）。
4. （随响度开回）`loudness` 只在真正结束时排空，不在暂时断粮时清延迟线。

预期：流式回答的句间/句末哒声消失；整段播放不变（它本来就规整）。验证＝上面两入口各一遍 +
"外接麦克风首末 20 ms 无可闻瞬态"。
