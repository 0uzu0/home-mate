## 4. 必须带入新桥的音频路径知识

历史实机记录的路径是：设备原始9通道、16kHz采集 → 七麦融合为一路mic → 与一路ch8硬件参考形成双通道上行 → NAS执行AEC。

- “七麦”不表示服务器收到七路独立mic。融合记录为低频七麦平均、高频中心麦。
- 当前记录的设备EchoMuse Speex AEC关闭。已有固件的普通设备AEC开关可能改变融合路径，不能通过简单开关迁移为新AEC方案。
- 参考提取/处理与mic必须对应同一时序。未来采用已处理语音接口还是mic＋ref接口，按设备桥合同和N1验证决定。
- 音量由设备管理，型号刻度和实际上报值由桥解释；本次不把瞬时音量写成新项目默认值。
- 客厅AUX/emOS与其他房间内置扬声器/FireOS路径不同。新桥应报告输入/输出profile及实际状态，底座不写设备ID分支。

## 5. 候选与已取消试验

- 设备侧AEC＋七麦组合仍属隔离候选，不能将其当作四台现役固件。候选版本动态维护于RUI HANDOFF的“隔离设备AEC候选停点”，本表不复制其“最新”指针。
- dot2-d蓝牙探索已取消并回滚，未将蓝牙作为RUI正式输出路径；Home Mate首期不因固件有蓝牙能力就自动启用。
- dot2-d声纹试用已关闭，其登记/录音不进入Home Mate Git；旧RUI四台声纹和全双工均不得因本记录恢复。新Home Mate的全双工目标按 [新交互要求](voice-interaction-and-control.md)单独设计验证，不把旧快照当新系统能力上限。
- 久置首唤醒、指令敏感度、自听和偶发音频交付间隔仍有未知；固件版本一致不是上述问题已解决的证据。
