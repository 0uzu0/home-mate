# RUI Local 经验迁移指南

更新：2026-11-07。用途：指导Home Mate开发者从旧项目提取经过验证的知识，按新接口重新实现并验证。指南初稿仅查阅本地资料，未导出现役配置或操作设备；后续用户要求记录四台Dot现状时已补充NAS只读API/日志快照，见[设备基线](dot-device-baseline.md)。没有复制私人录音、修改RUI或主动操作音箱。

本指南是[项目规划](plan.md)的迁移执行依据，受[架构原则](architecture-principles.md)与[设备桥边界](device-bridge-boundary.md)约束。资料提取与验证在后续开发授权范围内执行，不因本文自动开始设备操作。

## 1. 迁移的目标

迁移设备事实、参数及其适用条件、行为合同、失败经验与可复用验证材料。Home Mate自行设计模块、接口与数据结构，不继承RUI的源码转换链、运行时修改、历史兼容分支或多套语义决策入口。

每项资产都必须回答：从哪里来、针对什么版本和环境、已证明什么、没有证明什么、在新系统中由谁负责，以及如何验证迁移正确。不能只写“参考旧项目”，也不能把一份旧配置当作通用正确答案。

## 4. 参数提取方法

### 4.1 先建立四台设备清单

逐台记录稳定设备ID、房间、型号、固件来源与摘要、操作系统、实际输出方式和能力。HANDOFF曾记录客厅dot2为emOS＋AUX、HP11，b/c/d为FireOS＋内置扬声器、HP6；迁移前须核对这些事实仍成立。不能因为四台同型号就复用同一房间配置。

清单至少包含麦克风/参考来源、实际采样率与通道、AEC所有者、音量刻度/控制所有者、静音与停止能力，以及记录时间和证据位置。旧ID与新ID若不同，应保留映射，防止把一个房间的参数给另一台。

### 4.2 分层提取最终生效值和来源

逐项区分硬件事实、型号默认、全局策略、设备/房间覆盖、运行时状态和按条件推导的值。记录原系统实际优先级；新配置模型如何表达另行设计，不默认照抄旧合并顺序。

重点字段组：

- 音频格式、采集/封包/处理帧时长、mic/ref列与排列、融合方式。
- AEC位置、参考处理、对齐依据、tail/filter长度与单位、参考缺失时行为。
- KWS模型与关键词、阈值、增益的位置；VAD阈值、前后缓冲与结束条件。
- ACK具体音频/长度、播放时序、hold/裁切/尾窗和有限接话。相似字段名不能直接等同。
- 输出链、音量刻度/映射、曲线、限幅、缓冲、结束/flush语义与播放事实。

后续按RUI现有认证只读接口提取允许字段，例如 `/api/v2/devices/{id}/audio` 的effective配置、设备详情中的未知参数告警和 `/api/v1/audio?device_id=...` 的运行Metrics。先核对当时接口schema；字段不存在记录缺失，不按零值处理。避免直接输出整份配置或环境变量，它们可能包含凭证。

实现新音频链路前，逐台保存允许字段的脱敏快照和本地证据索引，记录采集时间、固件、房间、输出路径、AEC 所有者、参数来源及缺失字段。已有有效快照可复用，原始录音只保留本地索引。完整四台参数与可部署profile仍未提取；设备基线仅补充带时间的固件/连接与部分音频有效值，不能代替完整参数迁移。

### 4.3 每项参数附一条资产记录

记录格式在Home Mate实现时再定，至少有这些字段：

| 字段 | 要记录的内容 |
|---|---|
| 标识与范围 | 资产ID、字段语义、型号/设备/房间/全局范围 |
| 数值与单位 | 精确值、单位、采样率等换算前提；未知可为空 |
| 来源 | 仓库提交和文件，或有效配置回读时间/字段；敏感材料只留本地定位 |
| 适用条件 | 固件、输入/输出路径、算法版本、AEC位置、启用条件 |
| 证据类别 | 设备观测、用户反馈、真实录音回放、模拟、设计假设分别标记 |
| 结论边界 | 已证明的行为、未证明的效果、已知失败与反例 |
| 迁移决定 | 复用知识/重实现合同/仅供候选/拒绝迁移/待核实，及原因 |
| 验证入口 | 对应旧用例、录音索引和新系统检查条件 |

例如“600ms preroll”只能记录为特定已验证cue裁切后的hold回放条件，不得记成全局推荐值。HANDOFF记录其余live和有限接话仍为350ms，且某些双cue仍有未解决边界；两者必须一起保留。

## 5. 必须保留的经验边界

| 经验 | 新项目必须继承的判断 |
|---|---|
| 原始采集与上行不同 | HANDOFF记录原始9通道16kHz，生产上行为七麦融合一路mic＋ch8硬件参考一路；不能按“七麦”假定服务器收到7路独立mic |
| 固件支持AEC不等于已正确消回声 | 现役记录为设备AEC关、NAS AEC开；直接打开旧设备AEC可能退出融合路径。明确能力、请求、协商、实际启用与参考活动 |
| ACK尾音与轻声句首相互影响 | 同时保留纯提示音负例和提示结束后弱声正例，不能只延长屏蔽时间解决自听 |
| 等待音频不等于音频丢失 | “墙钟超过2秒就重置KWS”候选已被完整PCM延迟交付反例否决；不得作为成熟修复移植 |
| 断流残词模拟有收益，真实根因未定 | 保留残词与完整词仅暂停传输的成对案例；不把一次模拟当久置问题已解决 |
| 全局增加preroll可能纳入旧ACK | 保留 `audit/command-preroll-20261106@c5a2ef9` 反例；不将局部条件优化扩成所有输入 |
| 音频交付间隔不等于采样丢帧 | 服务调度、处理、同步日志和缓冲均可能影响交付；序号来源和时间轴要明确 |
| 视频中的人声仍是人声 | 非人声过滤不能消除所有视频误唤醒/接话；声纹曾在视频混音条件拒绝用户指令，现已关闭 |
| 把数据发出不等于用户听到 | 首PCM socket写入可作发送证据，不能冒称人耳确认；历史记录可能只代表提交 |
| 参数一致不等于四房行为一致 | 每台核对实际分支、保护挂载和执行合同；相同SHA/在线状态不能代替声学验证 |
| 引擎冷加载会放大首轮延迟 | 迁移共享预热的设计依据，同时保留房间历史/权限隔离；性能数值需注明样本与负载 |
| 检索返回候选不等于目标完成 | 故事不能自动降成歌曲，无匹配不能随机顶替；目标/约束由大脑保持，执行层核对候选依据 |

否决资料索引另有 `audit/kws-gap-reset-blocked-20261106@8de7f80`。这些分支作为证据读取，不checkout到另一位Agent的工作区、不把被否决代码合入新项目。

- 持久服务日志由HANDOFF定位。提取特定设备/时段的链路证据，注意UTC与北京时间；整理最小脱敏摘要，保留关联ID与证据等级。
- 本地 `02_Archive/` 中已有候选证据与镜像探针材料，按专项报告定位，不批量复制镜像和全部归档。

后续资产清单对外记录不含secret的索引、摘要、证据类别与可用性。原始材料无法取得时可迁移“历史结论＋边界”，但不得声称已在新实现上重放通过。

## 7. 验证迁移，而非逐行翻译旧代码

1. **先写可观察合同。** 从旧用例提取输入、时序、预期事件/输出、禁止动作和失败边界，不复制旧私有函数名或源码替换断言。
2. **新实现独立验证。** 用伪设备/本地PCM跑协议、通道、时长、取消、重连和旧事件隔离。检查Rust真实构建产物所用接口，不只验证孤立辅助函数。
3. **音频成对验证。** 在适用路径下比较相同PCM与时间轴；包含纯ACK、提示后弱声、晚cue/双cue、残词后恢复、完整PCM仅交付暂停等样本。
   纯提示音应产生零条指令，紧跟其后的轻声正例应保留句首并识别指令。完整 PCM 仅延迟到达时应保持连续识别状态；确有丢帧的样本单独记录缺口与恢复结果。两个测试分别保留输入时间轴。

   延迟分开记录用户说完到分段结束、排队等待解码、ASR 解码、模型首文本、合成与开始播音，各时间点注明观测位置。只有发送证据时记录首次发送时间。旧隔离实验使用 NAS、2 CPU/2 线程及同一份 1.75 秒音频，三次冷识别为 2641/2114/1799 ms，热识别为 214–282 ms。按相同条件比较，记录样本与负载。来源为 `rui-local@6a04e9a:docs/interaction-batch-20261106.md`。

4. **检查任务与工具事实。** 包含发送失败、部分发送、不确定、重复事件、取消后迟到、错误房间、同曲重播和搜索结果无关；不把流畅回复当执行成功。
5. **核对行为保持。** 普通唤醒与有限接话、暂停/插问/继续/停止、房间隔离、HA只开关、提醒不确定停止重播、音乐入库的合同分别检查。
6. **分别报告证据。** 配置校验、离线模拟、历史录音重放、安装运行和真实房间使用分开。语言/缓冲/引擎改变会使部分旧结果需要复验；指出变化及受影响范围，复用其他有效结果。

核心验收既包括旧能力，也包括新大脑的改写/纠正/多轮场景。旧系统的错误输出只能作为负例；不能要求新项目复现旧缺陷以保持兼容。

## 8. 迁移交付与完成条件

后续按功能批次交付以下内容，复用现有文档，不另建庞大管理框架：

- **资料清单**：提交/摘要、路径、可用性、现役/候选/历史/否决状态。
- **设备与参数清单**：四台身份、有效值与来源、物理/房间条件；未取到的字段明确待核实。
- **经验与合同**：采用或拒绝的理由、新模块归属、保持的用户决定、已知缺口。
- **验证结果**：执行版本、材料、命令/场景、通过与失败、证据边界，以及尚未验证的房间效果。

资产只有在来源和条件完整、新接口可表达且对应验证通过后，才能标为“已迁移验证”。其余使用“已登记”“待核实”“候选未验证”或“否决保留”，不能笼统标记“旧RUI经验已全部迁移”。

本轮状态：迁移指南已编写；上表是经本地路径核对的资料索引，已另行记录设备基线的只读子集，尚未完成完整现役参数提取或新实现验证。

## 9. 与项目阶段的衔接

- **N1前及N1中**：先核对资料、设备身份、信号路径与关键参数条件，设计最小版本化设备合同，再验证外部桥到Rust底座的音频/引擎接缝。不能等新音频链路定型后才发现格式或AEC所有者不同。
- **N2**：把旧执行、取消、回执合同接入新任务和工具接口，保留用户目标，避免移植旧语义分支。
- **N3**：在版本和路径可比的前提下迁移房间参数，运行旧正例/反例与新多轮行为验收，逐项更新资产状态。
- **N4**：后续授权下才进行实体设备试用和迁移；事先记录旧服务与恢复方式。未形成相应证据前不切换家庭音频路径。

旧RUI全双工、声纹、蓝牙的关闭事实与失败经验保留，迁移资料不改变其现役状态。新Home Mate已明确支持全双工、默认半双工并语音切换，按 [新交互要求](voice-interaction-and-control.md)设计验证，不能继承旧系统的“全双工取消”作为新产品禁令；声纹和蓝牙不自动启用。LX06后置，只保留历史经验。
