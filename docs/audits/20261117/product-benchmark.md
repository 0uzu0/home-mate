# Home Mate 同类产品对标与产品改进建议

调研日期：2026-11-17（北京时间）。项目基线：Core `c3ed6c6`，运行代码 `05da212`；Gateway `bbdfb3c` / `0.0.53`；现场 serial 69。本文是产品研究，不是缺陷清单，也不构成上线或扩展硬件范围的授权。

## 结论

Home Mate 已具备独立家庭助手的技术底座：每台设备独立 Core、本机网关、可分别配置 ASR/LLM/TTS、共享记忆层、工具执行事实和可编辑人设。相较大厂音箱，最值得发展的方向是 **中文家庭可掌控的助手：资料和记忆可查、动作可核实、接入可选择、家庭成员能够自己管理**。相较 Home Assistant，差异化应落在持续任务、家庭记忆和日常交互，而非单纯增加设备控制种类。

当前产品呈现仍偏开发者控制台：多数页面围绕服务连接、设备状态、参数与工具配置；家庭成员真正每天打开的“今天要做什么、刚才做成了什么、家里有哪些事”尚未形成统一入口。这个判断来自页面路由、工具清单和数据模型，不是对 UI 美观的主观打分。

不能据代码宣称 Home Mate 的唤醒、回声消除、响应速度或多房准确率超过竞品；目前没有相同声场、距离、噪声和内容的对照测量。工具回执、隐私分区等也必须结合本轮代码审计判断可靠程度，本报告只把已存在的机制视为可发展的结构基础。

## 对标方法与证据边界

- 只以官方使用指南、产品页和发布说明作为外部事实来源。使用指南能证明官方支持某功能，不能证明其在用户家中的可靠率。
- Google Gemini for Home 官方页面仍使用 early access 表述；地区、语言、硬件和订阅门槛必须一起阅读。当前支持表没有列出中国大陆或中文。基础家居控制、媒体、日历/清单/提醒与付费 Gemini Live 分开。[S4]
- Alexa+ 官方帮助页说明 Prime/付费及兼容设备要求；功能页是厂商声明，没有独立实测。不能据美国版功能推断中国大陆可用，更不能推断改装的 Dot2 可直接切到 Alexa+。[S3]
- HomePod 的家庭互通、个人内容依赖 Apple 账户/设备设置，语音识别受语言与地区限制。[S6][S7]
- 小米页面按具体产品型号使用；Xiaomi Sound 的全屋播放、传声、手机联动不能泛化为所有小爱音箱。NFC 接力还受兼容 MIUI/NFC/组件版本限制。[S8]
- Home Mate 的未发现功能，是在当前 Core 工具、API、前端和主要配置范围内未见第一方完整实现；通用 OpenAPI/socket 在外部搭建同类能力的可能性不等于已经交付该功能。

## 同类产品对照

| 产品 | 官方支持或声明的能力 | Home Mate 的结构优势 | Home Mate 的产品差距 |
|---|---|---|---|
| Home Assistant Assist / Voice PE | 本地或云端语音管线；可选择本地处理优先；实体曝光与别名；房间上下文；广播、定时器和家居自动化 [S1][S2][S10] | 对话任务、工具事实、家庭记忆和人格由一个自有 Core 组织，可按家庭需求深度调整 | HA 的设备覆盖、自动化编辑、手机端和社区集成更完整。“本地优先、可换模型”不是独家优势 |
| Amazon Alexa+ / Echo | 厂商宣称支持语音创建例程、家庭偏好记忆、日历/文档、跨设备访问、个性化内容 [S3] | 用户拥有并能修改执行逻辑、记忆管理与服务选择，不必把核心能力绑定单一厂商账户 | 缺少面向普通家庭的服务成套接入和日常任务界面；大厂的内容和第三方商业合作无法靠通用接口自动获得 |
| Google Gemini for Home / Nest | 基础家居、媒体、日历、清单和提醒；兼容设备上的付费 Live；广播与媒体移动有帮助文档 [S4][S5][S11] | 中文场景可以自行设计，供应商与本地算力可选择；每台 Core 的故障边界可控 | 手机与音箱的任务承接、家庭组织能力、内容发现深度更弱；不应把中文 UI 当作双语语音能力 |
| Apple HomePod / Siri | 房间/区域 Intercom、个人内容与成员声音设置、手机与家庭设备协同 [S6][S7] | 可接非 Apple 服务和自有接口；可管理的事实与来源记录更适合私有部署 | 账户、成员、个人终端和家中音箱的贯通体验尚未产品化 |
| 小米小爱 / Xiaomi Sound | 中文智能家居、可说指令展示、房间管理；具体型号支持家庭传声、全屋播放与手机接力 [S8][S9] | 供应商中立、可接自建服务，核心和长期记忆可掌控 | 中文家庭场景的即用模板、内容生态、手机协作与易用接入仍需补齐 |

这里的“结构优势”是本仓可检查的设计空间，不表示竞争对手完全没有相同能力，也不是本轮审计缺陷已经修复的声明。

## 八个新增产品方向＋一个既有路线扩展（均不计入 bug 修复）

优先级是研究建议，并非已批准的新 roadmap。成本 S/M/L 仅表示相对复杂度：S 主要利用现有 API 和界面；M 涉及新增领域状态、API/UI 与行为验证；L 还涉及跨服务、身份、语音或内容管线。所有验收数字都是建议目标，不是当前测量结果。

### 1. “这个家能做什么”能力中心与接入配方

- **场景**：家人想开空调、找新闻、播歌，能直接看到已可用能力、示例说法、依赖是否满足和适用房间；配置者选“接家庭曲库”即可逐步完成连接和验证。
- **依据**：小米官方说明其 App 列出支持设备及可说指令 [S9]；HA 提供可曝光实体及别名配置 [S2]。Home Mate 已有真实 Registry、availability 和服务探针，当前 UI 主要是配置卡。
- **增量**：由同一能力描述生成用户能力卡、常用说法、房间范围和接入向导；首批只为已有 HA、音乐、新闻与 OpenAPI 制作配方。每个配方明确权限、探针、成功示例与撤销接入操作。
- **优先级/成本**：建议第一批，S–M；依赖 Registry/配置 API。无需重建工具层或恢复已否决的 MCP 选型。
- **验收**：5 名未参与开发者各完成两项接入；≥80% 无工程师帮助在 10 分钟内成功；能力卡上的每个示例都能追踪至真实可用工具；连接失效时状态在下一次刷新可见。

### 2. 家庭广播与按房间传话

- **场景**：“告诉儿童房，十分钟后吃饭”；儿童房可回一句“知道了”。指定房间、全屋、静音房间例外都应明确。
- **依据**：HomePod Intercom 官方支持房间/区域与个人设备消息 [S6]；Google Android Gemini 提供按设备/房间/全屋广播，勿扰设备不播放 [S5]；Xiaomi Sound 有家庭传声 [S8]。
- **增量**：新增有限的 `household.announce` 产品行为，先做文字转语音广播和投递状态，再评估语音回复。当前 FleetPlaybackNotice 是协调元数据，不是家庭传话功能。
- **优先级/成本**：建议第一批，M；依赖设备目录、任务/播放回执和房间免打扰策略。只有在本轮仲裁/取消问题修复后才开展上线验收。
- **验收**：五台定向传话准确率 100%；重复投递不重复播；勿扰/离线/忙碌状态如实呈现；不把“播放完成”宣称为“家人已听见”；接收端可拒绝打扰。

### 3. 家庭日程、清单与提醒的统一入口

- **场景**：“明天谁接孩子”“把牛奶加入购物清单”“周五家长会别和补课冲突”。手机和语音看到同一个任务状态。
- **依据**：Gemini Home 的官方基础能力包括日历、清单、笔记和提醒 [S4]；HA 提供 to-do 列表语音操作 [S10]。
- **增量**：在现有单次提醒之上增加共享清单、责任人、完成/延期、周期规则与外部日历适配。先只读一个日历后端，写入逐项明确确认；NAS 可以保存共享状态，单台保留本机离线提醒。
- **优先级/成本**：建议第二批，M–L；身份、冲突处理、后台作业和移动界面必需。
- **验收**：两终端并发增删不丢项；重复事件不双建；时区、重复日程与取消操作覆盖确定性测试；离线时清楚区分缓存和已同步；确认后的跨设备可见延迟目标 ≤5 秒。
- **范围说明**：历史 v1 明确未承诺家庭日程，见 `docs/archive/d/m12a-decisions-20261114.md:38`。此项是新产品提案，不能当成当前缺陷或自动排期。

### 4. 可预览、可停用的家庭例程

- **场景**：“工作日七点拉开窗帘、播天气，周末不执行”；用户能看到触发条件、动作顺序和下一次执行时间。
- **依据**：Alexa+ 官方功能页描述语音创建例程 [S3]；Google Home 文档说明以自然语言生成可编辑自动化 [S12]。
- **增量**：用户说需求 → 生成有限结构化计划 → 页面/语音复述 → 确认启用。优先将设备自动化委托已有 HA，Home Mate 拥有意图、批准记录和执行摘要，不并行再造全部家居规则引擎。
- **优先级/成本**：建议第二批，M–L；依赖稳定工具合同、计划 schema、时区/调度和取消机制。
- **验收**：20 个固定家庭案例中生成的条件/目标/时间可由用户检查；未经启用的计划零执行；停用后无后续动作；单步失败清楚显示已执行与未执行项；恢复连接后不补放过时动作。

### 5. 可控制打扰程度的通知中心

- **场景**：天气突变、洗衣结束、某任务完成时，选择“现在说、等聊天结束、只发手机、晚间汇总”；问“刚才错过什么”能回看。
- **依据**：HA 官方 `ask_question` 支持主动提问与结构化回答 [S13]；Google 广播尊重勿扰设置 [S5]。
- **增量**：统一通知对象，具有来源、有效期、房间、重要程度、去重键、安静时段、用户订阅和回看记录。先接用户明确订阅的设备/任务事件，不依赖持续转写或推断家庭活动。
- **优先级/成本**：建议第二批，M；复用提醒播放协调，但产品语义另建。
- **验收**：安静时段非紧急播报为零；同一事件最多一个播报；过期通知不会迟到补播；每项订阅可单独撤销；屏幕上能解释为什么在此房间/此时发送。

### 6. 手机上的家庭任务卡与操作回执

- **场景**：音箱查到三首歌、一个菜谱或一项待确认任务，手机收到可继续操作的卡片；用户无需听完长列表，也无需进入诊断页找 trace。
- **依据**：Alexa+ 官方描述音箱、App 和网页访问以及发送对话摘要 [S3]；HomePod Intercom 的接收端包括个人设备 [S6]。
- **增量**：在现有 Vue 基础上建设移动优先 PWA：当前任务、候选选择、状态变化、结果链接、批准/取消与重试。它是家庭使用界面，管理控制台仍承载配置。第一版限定同一家庭 LAN，远程访问单独设计。首版需要确认的写操作仍在持有管理令牌的控制台完成；面向普通家庭成员的独立确认权限依赖第 9 项。
- **优先级/成本**：建议第一批，S–M；现有 chat/session/tasks API 已有基础，参见 `api/mod.rs:496-502`。
- **验收**：窄屏 360px 无横向滚动；键盘与读屏可操作；同一任务卡刷新后状态一致；语音与界面取消指向同一 task ID。成员/访客分级确认应在第 9 项身份与服务端授权完成后另行验收，不能以现有共享令牌宣称已具备访客隔离。

### 7. 带来源的家庭资料库

- **场景**：上传家电说明书、学校通知、常做菜谱，问“洗碗机滤网怎么拆”“周五活动需要带什么”，回答能指出具体文件和页码。
- **依据**：Alexa+ 官方功能页描述用户提供文档后提问/提取日程 [S3]。Home Mate 当前 notes/working memory/USER.md 存摘要与偏好，未见文档摄取、版本索引、页码引用和检索产品。
- **增量**：NAS 负责文档与索引，Core 只调用有 scope 的检索工具；回答引用原文位置，显示资料更新时间；删除文件后同步清除检索可见性。先支持文本/PDF，不扩展摄像头硬件。
- **优先级/成本**：建议第二批，M–L；需要文档解析/索引选型、许可复核、权限与删除语义。
- **验收**：固定家庭资料集的 30 个问题，≥90% 回答指向正确来源；无法支持的问题明确表示资料不足；改版后旧信息不会被标为现行；隐私文件跨成员不可见。

### 8. “断网仍能做什么”的可验证本地能力包

- **场景**：外网不可用时，时间、音量、定时器、精选家居指令仍可完成，用户在页面明确看到离线可用范围。
- **依据**：HA 官方全本地指南提供封闭指令与开放式识别两种路线，并明确语言/算力差异 [S1]。
- **增量**：Home Mate 已能配置局域网 API；新增按语言验证过的本地 ASR/TTS/有限意图配方和运行检查，优先利用现有 NAS/Mac 算力。不要将完整 ASR/LLM 默认塞入 512 MB Dot2，也不要让远端服务离线后无边界地等待。
- **优先级/成本**：建议第三批，L；实际模型/版本/许可、服务发现、失败切换和网络隔离测量是前置。
- **验收**：人为切断 WAN、保留 LAN 后固定 20 条能力集合全部有可解释结果；包内命令成功率目标 ≥95%；验证音频/文本无 WAN 出站；各语言分别验收，不以英文结果推断中文。

### 9. 成员、访客和儿童使用模式

- **场景**：家长和孩子有不同内容偏好、可调用工具和安静时段；访客可以问天气/播歌，但看不到私人记忆。
- **依据**：HomePod 官方成员设置把声音识别、个人内容和偏好联系起来 [S7]；小爱官方手册列出儿童模式 [S14]。
- **增量**：在 ScopeContext/USER.md 之上增加家庭成员注册、邀请、显式切换、可见范围、工具能力和使用时段的产品管理。先由用户在已认证界面选择身份；将来声纹仅提供识别候选，不作为敏感操作的唯一身份凭证。
- **优先级/成本**：建议第三批，L；这是对已计划 W4c 的产品扩展，声纹算法本身不计作本报告新增建议。
- **验收**：成员/访客矩阵每项能力均有服务端测试；未知声音只获得公共能力；撤销成员后会话/终端访问同步失效；家长能查看和撤回规则。

## 建议顺序与明确不建议追赶的内容

1. 代码审计中的高风险边界先修复并通过回归；不把修 bug 计为上述产品进展。
2. 第一批选 **能力中心＋手机任务卡**，快速让现有能力变得容易发现和使用；随后做定向广播，体现五台设备的价值。
3. 第二批在家庭日程、例程、资料库中选一个主场景，避免同时建设三个新状态系统。通知中心作为共同投递能力逐步形成。
4. 本地能力包和成员模式依赖更多基础验证；先做限定范围验证，再扩展。

不建议本轮恢复 #85 持续空闲转写、#81 MCP、#17/#18 双语语音议题，或提前进入 #11/#24/#40 全双工/S2S。它们已有项目裁定。同步多房音乐在 Google/小米有现成功能 [S8][S11]，但会增加时钟、缓冲和内容版权成本；历史 v1 也未承诺，暂列观察项，不算本报告的优先建议。故事跨房接续已有明确不做的历史决定，不以竞品对标为由复活。
