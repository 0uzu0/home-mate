# Agent内核：初步调研与后续选型任务

日期：2026-11-07。状态：官方资料层面的初筛，未安装、编译、调用模型或连接设备。用户认可Rust优先、借鉴成熟内核的方法；不限定Pi，也不默认全部自研。本文不代表采用某个依赖。用户已明确计划商用，内核选型同时按 [许可规划](commercial-licensing.md)审查；对接MCP/HA与工具的职责见 [接口与工具层](interfaces-and-tool-layer.md)。

## 1. 本轮决定与边界

- Home Mate大脑的主要推理仍由LLM提供，当前讨论基线为DeepSeek。Agent内核负责上下文、模型/工具循环、事件与控制，不自动带来更强模型能力。
- 优先Rust原生组件或Rust内的小型实现。仅为复用Agent内核，不默认再加Node.js/Python旁车和跨语言会话桥；若未来确有不可替代收益，应重新评估并说明整体代价。
- 该选择不禁止其他部分使用确有需要的推理/音频外部引擎，也不影响Vue＋TypeScript管理页面。浏览器使用TypeScript不等于服务器已经具有可供Pi复用的Node运行时。
- Pi、Hermes及其他项目可作为设计参考。复用方法或局部组件时检查来源、版本与许可，不把复制整个框架作为“从零设计”的捷径。
- 内核是可替换的内部实现。Home Mate保留自己的目标/任务/事实接口和执行边界；不能同时出现框架任务状态和底座任务状态各自决定是否还能执行的情况。

## 2. 初步候选与证据

以下是官方README中的能力说明与本项目的初步判断，未测量“轻量程度”、资源或实际模型表现。仓库main会变，后续验证须固定版本/提交并重新核对API。

| 路线/项目 | 官方资料能确认的定位 | 对Home Mate的初步判断与未验证项 |
|---|---|---|
| [Rig](https://github.com/0xPlaygrounds/rig) | Rust组件体系；当前README分别列出模型/工具合同的`rig-core`、Agent运行的`rig-agent`和独立记忆等模块 | 优先调查能否只用需要的模型/Agent组件，接入自有工具与事件。仓库还含编程工具/harness等能力，不能整套安装后就称轻量；DeepSeek具体接口、取消传播和最小依赖仍待验证 |
| [rust-genai](https://github.com/jeremychone/rust-genai) | Rust多供应商生成式AI客户端，列出DeepSeek及流式/工具相关接口，重点在模型API适配 | 作为“成熟模型客户端＋自有最小工具循环”的候选基础。它不是完整家庭Agent或任务运行器，循环、预算、事实与取消仍需Home Mate实现；不要与其他同名Gemini客户端混淆 |
| [ADK-Rust](https://github.com/zavora-ai/adk-rust) | Rust Agent框架，覆盖Runner、会话、工具、模型等，按组件/feature组织 | 补充候选与方法参考，先检查可裁剪范围、状态归属和API稳定性。功能覆盖广不能直接推断运行更重或更轻，也不因包含语音能力就替代本项目设备/AEC合同 |
| [Pi agent-core](https://github.com/earendil-works/pi/blob/main/packages/agent/README.md) | TypeScript Agent内核，提供上下文加工、工具执行钩子、事件和控制接口 | 主要学习方法。本轮不计划为它增加服务器侧跨语言运行时，不直接接完整coding-agent |
| Rust最小循环＋直接模型API | 项目自行实现所需模型协议与循环 | 必须作为成本对照，防止为简单需求引入整套框架；同时估算自己维护供应商差异、流式工具参数、错误和上下文协议的代价，不能假设几行循环就完成可靠Agent |

选型是不同层次的组合：模型客户端、工具循环、会话/记忆、家庭任务与设备执行分别判断。不要把一个客户端与一个完整运行框架按功能数量直接排名。

参考过的Pi SDK资料：[SDK](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/sdk.md)。它描述Node.js/Bun进程内的TypeScript集成及跨语言进程方式，正是需要计算新增边界的原因，不是声称技术上无法接入。

## 3. 值得借鉴的方法

### 统一循环与清晰阶段

每轮按“注入当前上下文→调用模型→解析提议动作→校验并执行→记录真实结果→必要时继续”组织。普通聊天允许首轮直接回答，不额外强制一次分类。不能通过固定场景分支代替用户意图理解。

### 模型上下文与运行事实分开

借鉴Pi的上下文加工边界，把房间事实、任务目标、最新修正和相关历史在请求前整理成模型上下文。用于界面展示的事件不必全部送入模型；已生成、已发送和未知状态保留区分。

框架消息列表不是设备事实数据库；长期偏好、活动任务、执行事件和模型上下文各有明确来源，避免保存两份互相竞争的真相。

### 工具前后钩子

执行前核对目标、房间、授权、参数、候选依据与任务有效性；执行后以真实回执进入下一轮。钩子是通用接缝，不是在钩子中堆故事/音乐专用关键词。

Pi当前文档支持前后工具钩子和事件流，可作设计参考。是否并发执行工具由语义和资源约束决定，不能照搬任何框架默认值。

### 停止与纠正分开

运行中追加“换一种做法”与立即取消是不同操作。Pi文档中的steering在某些路径等待当前工具完成后进入下一轮；不能把它当音箱即时停止机制。Home Mate底座立即失效旧任务/停止输出，模型与工具的取消传播随后验证；已经发生的设备动作不能靠取消倒回。

### 事件流服务于管理与诊断

统一呈现模型文本、工具开始/完成、错误和任务状态，但框架的agent结束不等于设备播放结束。管理页面从同一事实来源展示进展与配置，复用既有交付要求。

以上属于从项目方法中提炼的设计建议，不是宣称这些框架已经证明了Home Mate的多房、音频或取消合同。

## 4. 后续开发Agent的调研任务

在N0.1明确首批场景后，N1按以下顺序执行；当前已有首批隔离开发授权，具体实验范围见 [HANDOFF](HANDOFF.md)：

1. 更新有限候选清单：优先查Rig与“Rust模型客户端＋最小循环”，必要时补ADK-Rust；允许有依据地增删，不限定Pi、不做无边界框架搜集。
2. 固定拟采用的release/commit、license、Rust工具链、最小features与目标NAS构建条件。核对具体包及传递依赖的商业发行义务，不能只看根LICENSE；核实DeepSeek具体模型和流式工具协议，不把“OpenAI兼容”当完整验证。
3. 根据实际代码检查：工具参数流拼接/校验、事件次序、串并行工具、错误和超时、取消、上下文注入、历史恢复、调用预算与重复调用终止。
4. 画出与Home Mate的接缝：谁拥有房间、任务、事实、消息和配置；内核如何接入Home Mate工具合同、MCP适配和媒体能力，再发出动作建议与接收真实结果，如何被替换。模型协议代码和框架类型不扩散到设备桥。
5. 比较最小接入的总复杂度：传递依赖、运行时/进程、适配代码、维护职责、API变化、调试和测试成本。未构建前不宣称二进制小、内存低或取消可靠。
6. 先读代码淘汰不合适项，再只对最有希望的1–2条路线做小型隔离验证；复用同一组场景与工具假实现，不建设两套完整系统。
7. 交付一份选型结论：复用哪些组件、自己实现哪些机制、拒绝其他路线的依据、未解决风险、版本固定和替换边界。独立评审后更新正式技术选择。

不默认把Rust内核移植写成对Pi或任何框架的逐行翻译，也不把“没有使用框架”作为优点本身。评估目标是长期总维护成本和行为正确性。

## 5. 最小对比场景

| 场景 | 核对点 |
|---|---|
| 简短聊天 | 首轮直接流式答复；没有多余分类/工具调用 |
| 查询后执行 | 保留目标，正确消费查询结果，动作经底座核对，结果回传模型 |
| 请求执行中纠正 | 更新要求后不继续旧方向；明确哪些旧动作已发生、不能撤回 |
| 工具失败/结果无关 | 能换方法或如实报告，不重复同参调用到失控，不用随机结果顶替 |
| 取消与迟到 | 模型、工具、输出队列按各自边界停止，旧任务不再提交新动作，已经发出的动作按设备回执记录，停止未确认时保留未知状态 |
| 双工与语音管理 | 持续输入/输出事件与模式切换能接入共同任务/配置合同；换音色与诊断有真实能力和回执，不以steering队列代替即时停止 |
| 两个房间并发 | 历史、任务和动作隔离；受限资源与工具并发策略明确 |
| 配置、事件与恢复 | 使用共同配置接口；管理页面可理解进展，历史与事实恢复不造成重复执行 |

先用确定性假模型/工具检查合同；首批隔离开发已获授权，用同一DeepSeek模型和近似一致的提示/工具定义比较实际决策，避免用不同模型效果给框架排名。真实模型测试只接假设备动作。

记录模型调用次数、工具次数、首文本/首声边界、完成延迟、资源、错误及取消结果；将测量条件与未测项写明。不预设框架必然更快，也不把文本流式等同于音箱首声。

## 6. 当前结论与接续（M3.5 调研归档，2026-11-07 更新）

**M3.5 第一步已完成**：四个独立调研智能体（与实现者分离）对候选逐一深研并归档于 [kernel-research/](kernel-research/) 目录——[Rig](kernel-research/rig.md)、[rust-genai](kernel-research/rust-genai.md)、[ADK-Rust](kernel-research/adk-rust.md)、[其他候选全景扫描](kernel-research/landscape-scan.md)。各报告含固定版本/许可/MSRV、实际 API 语义（含取消传播）、接缝分析、维护风险与带来源的结论。

**综合结论（三深研＋一扫描一致）**：

| 候选 | 固定版本 | 许可 | 一句话结论 |
|---|---|---|---|
| Rig | `=0.46.0`（2026-10-31，MIT，MSRV 1.97.1） | MIT（含 CDLA-Permissive-2.0 的 webpki-root-certs 待审） | **只借方法**；模型客户端层可选试点（需 bigmodel 实测 spike）；不接 rig-agent 循环（hook 驱动取消＝在途工具"排空而非中止"，与语音硬停语义冲突；run 状态机共掌控制权；resume 会重执行未答调用）。ARC 代币资金背景记入商用评审 |
| rust-genai | `=0.7.3`（2026-11-03，MIT/Apache-2.0） | MIT OR Apache-2.0 | **当前保留自写客户端**；多供应商需求出现时（音箱内 Ollama 研究是天然触发点）经 LlmClient trait 替换，估 1–2 天；bigmodel v4 一等适配器＋GLM-4 流式怪癖回放测试是最大吸引力；注意 bare `glm-*` 会路由到 z.ai，必须用 `bigmodel::` 命名空间 |
| ADK-Rust | `=2.3.0`（2026-10-09，Apache-2.0，MSRV 1.95） | Apache-2.0（cargo-deny 全仓只许宽松许可） | **只借方法**——其取消语义是全场最成熟（interrupt＋为每个在途调用合成 OutcomeUnknown 回答、RunBudget 多轴预算、ErrorCategory 含 Cancelled）；但 Runner 必然共掌会话/运行/在途状态，违反单一任务状态归属红线；作为未来持久编排的后备记录 |
| 全景扫描 | — | — | **没有漏掉重量级候选**；建议补研两个：**langchain-rust**（v8.0.0，唯一有流式事件＋取消＋SQLite 记忆的活跃 Rust 框架；churn/单人维护为风险）与 **graph-flow**（可恢复/可暂停/人工中断的工作流层，不抢模型访问，与现有候选组合而非竞争）；agent-framework（MS AF 移植）仅观察 |

**三个深研报告共同的可偷方法清单**（进 Home Mate 自有循环的 backlog，非依赖）：
1. Rig 的流式分片序列模型（Part 编号、Start→grow→End 校验、部分参数可解析）与"取消时输出规范闭合历史"；精确 max_turns 语义；retry-after 解析与 Stalled 空转分类。
2. ADK-Rust 的 OutcomeUnknown 在途回答合成（与 Home Mate 迟到结果补记语义同构，可为下一轮模型上下文提供更诚实的取消叙事）；RunBudget 多轴预算＋预算耗尽持久事件；ErrorCategory 分类；分层状态键（app:/user:/temp:）；工具效果分类（只读/幂等/非幂等）驱动并行与重试。
3. rust-genai 的 bigmodel 适配器与超时语义（header/read 双超时≈本项目首事件超时）作为未来替换时的对齐基线。

## 7. 原"当前结论与接续"（2026-11-07 初筛时，历史保留）

本轮确认Rust原生路线值得继续调查，Pi等项目的方法可借鉴。还没有证据确定应采用某个框架，或自有循环的总成本更低。

正式立场：**Rust优先、接口可替换、优先复用适合的组件；不为Agent内核默认增加跨语言运行时，也不先决定全部重写。**

本次只更新研究和规划；没有安装依赖、写运行代码、执行模型对比或改变现役RUI。
