## 从零开发与经验复用

- 不在旧`rui-dot2-bridge`续写，不重命名、接管、合并或整仓复制旧桥；新仓库不以旧Python实现作为运行依赖。
- 只读提取已验证的握手/设备协议、音频布局、停止/重连语义、音量映射、固件差异、房间参数及失败场景。按[经验迁移指南](rui-experience-migration.md)保存来源、适用条件、证据和未知项。
- 重新实现不等于重新做全部真人测试，也不等于重做Dot固件。优先使用已有录音、日志和定向模拟；私有录音、完整配置和凭证不进Git。
- Dot适配首先在设备网关工程内部按明确模块边界实现；不预建每个型号一个仓库，也不先做插件市场。LX06仍后置。

## 与底座的边界

网关负责硬件协议、实际连接/重连、原始媒体布局、硬件参数映射、播放/停止及设备状态翻译。大脑的用户意图、业务工具选择和家庭任务生命周期不转移到网关。AEC位置根据输入合同与验证确定，不能因命名为网关就强行搬移所有通用音频处理；详见[设备网关与底座边界](device-bridge-boundary.md)。

双方仅通过版本化公开合同协作。底座不导入网关内部类型，网关不读底座数据库/私有配置。共享schema或测试样例需记录明确版本与权威来源；首批不必再建第三个仓库，不能通过跨仓相对路径、共享源码目录或未标版本的复制保持“同步”。两个工程分别可构建、测试和发布，协议版本与软件版本分开。

## 设备网关里程碑的建仓与开发交接

1. 阅读Home Mate的[HANDOFF](HANDOFF.md)和本文件，检查两个目标目录/远端是否已有工作。若同名仓库已存在，先核对归属与内容，不覆盖或重置。
2. 在上述本地目标目录初始化新工程，创建对应**私有**GitHub仓库并核实可见性，提交和推送。此建仓已由用户指示，无需再询问是否允许；不能用另一个旧桥仓库替代。
3. 新仓库写入自己的README、AGENTS和HANDOFF，记录启动/测试方式、首期范围、依赖许可、旧经验来源与未完成项；从入口链接回Home Mate合同。不得提前指定自有开源许可证。
4. 规划设备协议验证时，可用外部虚拟终端与 Home Mate 真实进程连接，检查握手、能力、任务/连接代、取消、迟到结果和断线。可参考主仓[验证案例](HANDOFF.md)模拟已缓冲播放时断线、迟到回执和双终端唤醒。网关按合同提供带终端来源与时序的事件或音频，唤醒检测的位置由音频合同明确。四房部署由 NAS 底座在播出“在呢”前选出唯一应答端。模拟结果明确标记，不宣称Dot声学已验收。Dot硬件实现随后在本仓推进。
5. 两个仓库各自记录合同版本、实际提交与检查结果，相互链接；更新Home Mate交接中的真实仓库地址与创建状态。不可只建空仓就报告网关已经完成。

本次只更新规划与交接；未创建新网关仓库、启动网关或变更旧RUI。实体接管、刷机与生产切换仍按Home Mate HANDOFF的后续范围执行。
