# M3 真实模型验证记录（2026-11-07）

场景集：`scripts/verify_m3.py`（确定性孪生见 `crates/hm-core/tests/scenarios.rs`）。
运行环境：真实 GLM `glm-4-flash`（bigmodel v4），模拟工具层，无已连接设备（播放走模拟回执并如实标注）。
复跑方式：核心运行中执行 `python3 scripts/verify_m3.py [base_url]`；注入场景需以 `HM_INJECT_PLAY_FAIL=t01` 启动核心并设 `HM_VERIFY_INJECT=1`。

## 第一次运行（修复前，暴露真实缺陷）

对旧提示词的运行（实例 `127.0.0.1:8930`，M2 二进制）：口语化说法「现在网上大家都在听的歌，来一个呗」**未调用任何工具**（`chain=False, plays=[]`），模型凭记忆编造榜单（「热门歌曲 1」等，均不在模拟数据集），后续轮还虚构「(播放中)」。经典说法（「放一首热榜上的歌」「来首榜上最火的」）则正常走 hotlist→play 并以回执作答——缺陷是**说法依赖**的，不是链路性的。

结论：循环契约（确定性测试已钉死）没有问题；是真实模型在高度口语化输入下跳过工具、违反「回执为准」红线。

## 修复（最小改动）

`crates-hm-core/src/agent/prompt.rs` 规则 2 收紧为：外部现状/动作必须调用工具，**禁止凭记忆编造榜单、曲目或播放状态；没有工具回执不得声称已完成**。通用行为约束，无场景关键词（既有单测 `prompt_is_generic_no_scenario_keywords` 继续通过）。

## 第二次运行（修复后，5/5）

新二进制，隔离实例（独立端口 8935/8936，数据目录为副本），同一真实模型：

## 边界

- 真实模型场景本身非确定性：glm-4-flash 在个别说法上仍可能多变；本记录证明的是契约与提示词约束下的通过态，后续换模型需复跑。
- 取消场景的等待窗口依赖真实模型时延（首调用通常够长）；极端快速完成时该场景按「已完成＋取消未受理」如实判定。
- 无设备路径的播放为模拟回执（SSE/trace 明示），deviceconfirmed 证据等级来自模拟 sink，不代表实机。
